## What is Neon?

Neon is a **serverless PostgreSQL** database designed for modern applications. It's perfect for Vercel deployments because:

- ✅ **Serverless:** No server management, auto-scales
- ✅ **Connection Pooling:** Built-in (essential for serverless)
- ✅ **Branching:** Git-like branches for dev/staging/prod
- ✅ **Instant Backups:** Point-in-time recovery (7 days)
- ✅ **Free Tier:** 0.5 GB storage, unlimited compute time

## Step 5: Update Prisma Schema (5 minutes)

Your current schema needs one small change for Neon:

**File:** `libs/database/prisma/schema.prisma`

**Before:**
```prisma
datasource db {
  provider = "postgresql"
}
```

**After:**
```prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")  // ← ADD THIS LINE
}
```

**Why?**
- `url` → Uses **pooled connection** (fast, for queries)
- `directUrl` → Uses **direct connection** (for migrations)

**Save the file.**

## Step 6: Apply Migrations (15 minutes)

### Important Safety Rules
- ⚠️ **NEVER** use `prisma db push` in production
- ⚠️ **NEVER** use `prisma migrate reset` in production
- ✅ **ALWAYS** use `prisma migrate deploy`

### Step 6.1: Create Neon Branch for Testing

1. In Neon dashboard, click **"Branches"**
2. Click **"Create Branch"**
   ```
   Branch Name: staging
   Parent Branch: main
   ```
3. Get the staging connection strings
4. Test migrations on staging first!

### Step 6.2: Apply Migrations to Staging


## Troubleshooting

### Problem: "Connection timed out"
**Cause:** Firewall or SSL issue  
**Solution:**
- Verify `?sslmode=require` is in connection string
- Check your network allows outbound port 5432
- Try from a different network

### Problem: "too many connections"
**Cause:** Using direct connection instead of pooled  
**Solution:**
- Use the **pooled connection** string (has `-pooler` in hostname)
- In Prisma, set `url = env("DATABASE_URL")` to pooled connection

### Problem: "password authentication failed"
**Cause:** Incorrect password or username  
**Solution:**
- Reset password in Neon dashboard
- Copy the new connection string exactly

### Problem: "database does not exist"
**Cause:** Database name mismatch  
**Solution:**
- Verify database name in Neon matches connection string
- Default is `neondb`, but you can rename it

### Problem: "migration failed"
**Cause:** Existing tables or schema mismatch  
**Solution:**
- Use Neon branch for testing first
- Check migration order (migrations must be sequential)
- Verify no manual schema changes were made

## Neon Free Tier Limits

**Storage:** 0.5 GB
- Your database will use ~50-100 MB with seed data
- Safe limit: ~200 MB (leaves room for growth)

**Compute:** Shared (no limit on compute time)
- Auto-pauses after 5 minutes of inactivity (free tier)
- Wakes up instantly on first query (~300ms cold start)

**Connections:** No hard limit
- Pooled connections recommended for serverless
- Direct connections limited to ~100 concurrent

**Branches:** 3 branches
- Recommended: `main`, `staging`, `dev`

**Backups:** 7 days of history (point-in-time recovery)
